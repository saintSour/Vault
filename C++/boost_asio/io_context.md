# 🌐 io_context

> [!abstract] Суть темы
> boost::asio::io_context - главный диспетчер событий и одновременно очередь задач. Он связывает программу с системными механизмами ввода-вывода и выполняет обработчики (handlers)

---

## 🧠 Ключевые концепции и Жизненный цикл
*Связанные темы:* 
- [[work_guard]],

**Роль в архитектуре:**
Реализует паттерн *Proactor*. Служит фабрикой и контекстом исполнения всех I/0-объектов (сокеты, таймеры, каналы)

### 🔄 Потоковая модель и Контекст выполнения
- **Потокобезопасность:** [Только отдельные методы]. Отдельные методы (например, `post()`, `dispatch()`, `stop()`) потокобезопасны. Вызов `run()` можно делать одновременно из нескольких потоков для создания пула воркеров. Однако сами I/O-объекты, привязанные к контексту, потокобезопасными не являются и требуют синхронизации (через `strand`).

## 💻 Сигнатуры и Код (MRE)

### Минимальный рабочий пример
 ```cpp
#include <boost/asio.hpp>
#include <iostream>
#include <memory>

namespace asio = boost::asio;
using asio::ip::tcp;

int main() {
    try {
        asio::io_context io;

		// 1. Постановка простой задачи напрямую в очередь
        asio::post(io, []() {
            std::cout << "[Thread " << std::this_thread::get_id() 
                      << "] Задача из очереди выполнена\n";
        });
        
        // 2. Имитация асинхронного таймера
        asio::steady_timer timer(io, std::chrono::milliseconds(100));
        timer.async_wait([](const boost::system::error_code& ec) {
            if (!ec) {
                std::cout << "Таймер сработал!\n";
            }
        });
        
        io.run();
    } catch (const boost::system::system_error& e) {
        std::cerr << "Error: " << e.what() << std::endl;
    }
    return 0;
}
```

### 📋 Важные методы
- **`run()` / `run_for()` / `run_until()`:** Блокирует вызвавший поток и выполняет готовые обработчики, пока есть зарегистрированная работа. 
- **`poll()` / `poll_one()`:** Выполняет готовые задачи без блокировки (non-blocking) и сразу возвращает управление. 
- **`stop()`:** Принудительно останавливает цикл событий. Не завершает оставшиеся задачи. 
 - **`restart()` / `reset()`:** Переводит контекст из состояния «остановлен» в готовность к повторному запуску `run()`.

## ⚠️ Подводные камни и Управление памятью (Gotchas)

> [!danger] Время жизни объектов (Lifetime Issues)
> - **Преждевременный выход из `run()`:** Если на момент вызова `io.run()` нет активных асинхронных операций (или сокетов/таймеров), он завершится **мгновенно**, не дожидаясь будущих задач. 
>   - **Решение:** Использовать `make_work_guard(io)`, чтобы искусственно удерживать `run()` активным. 
> - **Исключения внутри Handler:** Если обработчик выбрасывает необработанное исключение, оно покидает пределы `run()`, прерывая обработку остальных событий. Контекст переходит в остановленное состояние; для продолжения требуется перезапуск через `io.restart()` и повторный `io.run()`. 
> - **Блокирующие операции внутри цикла:** Вызовы `std::this_thread::sleep_for()`, тяжелые вычисления или синхронный I/O внутри обработчика замораживают поток, в котором крутится `io.run()`, блокируя обработку всех остальных сетевых клиентов на этом контексте.

### 🚀 Способы интеграции / Асинхронные парадигмы
- [x] **Callbacks:** Базовый сценарий вызова обработчиков через лямбды или свободные функции. 
- [x] **Work Guards:** `asio::executor_work_guard<asio::io_context::executor_type>` для фоновых сервисов. 
- [x] **Пул потоков:** Запуск нескольких потоков `std::jthread([&io] { io.run(); })` на одном экземпляре `io_context` для параллельной обработки событий. 
- [ ] **C++20 Coroutines:** Служит средой исполнения для сопрограмм, запущенных через `asio::co_spawn(io, ..., asio::detached)`.
